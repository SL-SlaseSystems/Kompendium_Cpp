# C++17

C++17 ujednolicił wiele codziennych idiomów. Język otrzymał structured bindings, `if constexpr`, inline variables, fold expressions, init-statements w `if` i `switch`, gwarantowaną copy elision w określonych przypadkach oraz class template argument deduction. Biblioteka dodała `optional`, `variant`, `any`, `string_view`, `filesystem`, parallel algorithms i `std::byte`.

~~~cpp
#include <cassert>
#include <map>
#include <optional>
#include <string>

std::optional<int> lookup(const std::map<std::string, int>& values,
                          const std::string& key) {
    if (const auto it = values.find(key); it != values.end()) {
        return it->second;
    }
    return std::nullopt;
}

int main() {
    const std::map values{std::pair{std::string{"answer"}, 42}};
    const auto result = lookup(values, "answer");
    assert(result.value_or(0) == 42);
}
~~~

Initializer w `if` ogranicza iterator do obu gałęzi instrukcji. CTAD dedukuje parametry mapy, choć w publicznym kodzie jawny typ może być czytelniejszy. Optional oddziela brak wyniku od sentinel value.

`if constexpr` umożliwia warunkowe odrzucenie gałęzi podczas instancjacji i uprościł wiele wzorców SFINAE. Fold expressions zastąpiły rekurencyjne rozwijanie packów. Inline variables rozwiązały część problemów definiowania stałych i obiektów w nagłówkach.

Execution policies pozwalają żądać wykonania sekwencyjnego, równoległego lub wektoryzowanego, ale kontrakt funkcji użytkownika staje się bardziej restrykcyjny. Dostępność backendu i realny stopień równoległości są implementacyjne.

C++17 pozostaje częstym baseline bibliotek, lecz nowy kod korzystający z concepts, ranges, jthread i span wymaga C++20. Nie emuluj nowego API własnymi makrami, jeśli można rozsądnie podnieść minimalny standard.

## Jak to działa krok po kroku

W pierwszym przykładzie `find` wykonuje wyszukiwanie, a instrukcja `if` ogranicza zakres iteratora do sprawdzenia i obu gałęzi. Gdy klucz istnieje, liczba jest kopiowana do `optional<int>`; gdy nie istnieje, zwracany jest pusty stan. Wywołujący nie musi interpretować umownej liczby `-1`, która mogłaby być prawidłową wartością mapy.

To charakterystyczny kierunek C++17: modelowanie informacji w typie i ograniczanie pomocniczego stanu. Structured bindings pozwalają nadać nazwy składowym wyniku, a inicjalizatory instrukcji skrócić czas życia lokalnej zmiennej. Uproszczenie składni nadal wymaga decyzji, czy rozpakowywany obiekt jest kopiowany, czy oglądany przez referencję.

## Pogłębienie mechanizmu

`auto [a, b] = object` tworzy ukryty obiekt, z którego udostępnia składowe. `auto& [a, b] = object` wiąże się z oryginałem. Dlatego pętla po mapie z `auto [key, value]` zwykle pracuje na kopii pary, a `auto&` daje dostęp do elementu kontenera. W mapie klucz pozostaje niemodyfikowalny przez taki dostęp, ponieważ jego zmiana mogłaby naruszyć porządek struktury.

`if constexpr` odrzuca gałąź podczas instancjacji odpowiedniego szablonu. Nie działa jak preprocesor: kompilator nadal musi rozpoznać poprawną składnię, a nazwy niezależne od parametrów podlegają właściwym regułom wyszukiwania. Poza kontekstem szablonu `if constexpr(false)` nie jest sposobem na ukrycie dowolnego błędnego C++. Do wycinania nieobsługiwanego API służy często `#if`.

Gwarantowana eliminacja kopii dotyczy określonych inicjalizacji z prvalue tego samego typu. Nie należy utożsamiać jej z NRVO dla nazwanej lokalnej zmiennej, które nadal jest opcjonalną optymalizacją. Możesz zwrócić `return T{};` także wtedy, gdy typ nie daje się kopiować ani przenosić, o ile spełnione są pozostałe wymagania, w tym dotyczące destruktora. Dopisanie `std::move` nie jest ulepszeniem tej konstrukcji.

## Drugi przykład

~~~cpp
#include <cassert>
#include <string>
#include <type_traits>

template<class T>
std::string describe(const T& value) {
    if constexpr (std::is_integral_v<T>) {
        return std::to_string(value);
    } else {
        return value;
    }
}

struct Token {
    Token() = default;
    Token(const Token&) = delete;
    Token(Token&&) = delete;
};

Token make_token() { return Token{}; }

int main() {
    assert(describe(42) == "42");
    assert(describe(std::string{"tekst"}) == "tekst");
    [[maybe_unused]] auto token = make_token();
}
~~~

Dla `int` druga gałąź nie jest instancjowana; dla `string` odrzucona zostaje próba `to_string`. To niewielki przykład zamierzonego zbioru typów, a nie uniwersalny formatter: `describe` dla dowolnej klasy może się nie skompilować. `Token` pokazuje osobno inicjalizację wyniku bez wymagania konstruktora kopiującego i przenoszącego.

## Porównanie i decyzje

`optional` reprezentuje brak wartości, `variant` wybór jednej z zadeklarowanych alternatyw, a `any` przechowuje obiekt o ukrytym typie z kontrolowanym odzyskaniem konkretnego typu. Wybierz najmniejszy zbiór stanów opisujący problem. Jeśli błąd ma zawierać przyczynę, samo `optional` może być za ubogie; przy bazie C++23 rozważ `expected`.

`string_view` ogranicza kopiowanie tekstu, ale nie przejmuje własności. Zastąpienie nim pól typu `string` bez analizy lifetime może pogorszyć poprawność aplikacji. Podobnie polityka `par` nie jest automatycznym przyspieszeniem algorytmu: narzuca dodatkowe warunki na operacje użytkownika i wymaga rzeczywistej możliwości równoległego wykonania.

## Ćwiczenie z odpowiedzią

Zamień `return Token{};` na lokalne `Token result; return result;`. Czy usunięte kopiowanie i przenoszenie pozostają bez znaczenia? Nie: NRVO dla nazwanej zmiennej nie jest obowiązkowe, a program musi spełniać reguły związane ze zwracaniem takiego obiektu. To odmienny przypadek od bezpośredniego utworzenia wyniku z prvalue.
