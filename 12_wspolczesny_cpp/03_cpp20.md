# C++20

C++20 wprowadził concepts, ranges, korutyny, moduły, spaceship operator, designated initializers dla agregatów, rozszerzone `constexpr`, `consteval`, `constinit`, `char8_t` i wiele ulepszeń lambd. Biblioteka dodała `span`, `jthread`, stop tokens, semaphores, latch, barrier, format, calendar/time zones, `source_location`, bit operations i atomowe wait/notify.

~~~cpp
#include <cassert>
#include <concepts>
#include <span>

template<std::integral T>
T sum(std::span<const T> values) {
    T result{};
    for (T value : values) {
        result += value;
    }
    return result;
}

int main() {
    const int values[]{10, 20, 12};
    assert(sum<int>(values) == 42);
}
~~~

Concept dokumentuje, że operacja ma sens dla typu całkowitego, a span przekazuje zakres z rozmiarem. Ranges zmniejszają potrzebę ręcznego przekazywania par iteratorów, lecz wprowadzają istotne reguły lifetime views.

Moduły i korutyny są mechanizmami języka, a nie kompletnym systemem budowania ani runtime’em async. Korutyna potrzebuje typu zwrotnego definiującego promise oraz awaitable objects. Moduły wymagają, by build system zbudował graf zależności.

Three-way comparison może generować spójny zestaw operatorów, ale rodzaj porządku — strong, weak lub partial — zależy od składowych. Floating point prowadzi do partial ordering ze względu na NaN.

Wsparcie C++20 dojrzewało nierównomiernie, szczególnie dla modułów, format i stref czasowych. Flaga standardu nie wystarcza; sprawdzaj feature-test macros i macierz wersji biblioteki.

## Jak to działa krok po kroku

Przykład `sum<int>(values)` łączy trzy niezależne etapy. Najpierw jawny argument określa `T` jako `int`. Następnie constraint `integral` sprawdza kategorię typu. Przy wywołaniu tablica jest konwertowana do `span<const int>`, który przenosi informację o rozmiarze i daje niewłaścicielski dostęp do elementów. Sama suma jest obliczana podczas wykonania.

Dlaczego podano `<int>`? Dedukcja parametrów szablonu nie przeszukuje dowolnych konwersji użytkownika, aby odgadnąć `T` z tablicy w miejscu `span<const T>`. Jawny argument oddziela dedukcję od późniejszej konwersji. To ważne również przy projektowaniu własnego API przyjmującego widoki: czytelny typ parametru nie gwarantuje automatycznie takiej samej wygody dedukcji dla każdego argumentu.

## Pogłębienie mechanizmu

Concept opisuje wymagania typów i wyrażeń. `integral<T>` nie dowodzi, że suma danych zmieści się w `T`, ani że `bool` jest sensownym typem akumulatora. Wymagania składniowe oraz semantyczne operacji pozostają różne. Ograniczenia szablonu poprawiają wybór przeciążeń i diagnostykę, lecz wartości wejściowe nadal mogą wymagać sprawdzenia podczas wykonania.

`span` i views nie dodają automatycznej ochrony przed wszystkimi błędami zakresu. `span::operator[]` w C++23 wymaga poprawnego indeksu. Widok `filter` może dodatkowo korzystać ze stanu własnego obiektu i bazowego zakresu. Otrzymanie krótkiej składni potoku nie usuwa zależności czasów życia.

Operator `<=>` zwraca kategorię porządku. Dla liczb całkowitych zwykle jest to porządek silny, a dla zmiennoprzecinkowych częściowy z powodu NaN. Domyślne porównanie klasy przebiega po bazach i polach w ich kolejności. Dodanie pola może więc zmienić znaczenie porównania, mimo że nadal wszystko się kompiluje. Porządek biznesowy powinien być świadomym kontraktem.

`constinit` zapewnia określony rodzaj inicjalizacji obiektu o statycznym lub wątkowym okresie przechowywania, ale nie czyni go niezmiennym. `consteval` nakazuje obliczenie odpowiednich wywołań funkcji w kontekście natychmiastowym. `constexpr` dopuszcza obliczanie w czasie kompilacji przy spełnionych warunkach. Podobieństwo nazw nie oznacza zamienności tych słów.

## Drugi przykład

~~~cpp
#include <cassert>
#include <compare>
#include <concepts>

struct Version {
    int major;
    int minor;
    auto operator<=>(const Version&) const = default;
};

constinit int counter = 0;
consteval int compile_time_limit() { return 8; }

int main() {
    static_assert(std::totally_ordered<Version>);
    static_assert(Version{1, 9} < Version{2, 0});
    static_assert(Version{2, 0} == Version{2, 0});
    constexpr int limit = compile_time_limit();
    static_assert(limit == 8);
    ++counter;
    assert(counter == 1);
}
~~~

Porównanie sprawdza najpierw `major`, a dopiero przy jego równości `minor`; nie sumuje pól. `counter` wolno zmienić mimo `constinit`. `totally_ordered` sprawdza dostępność właściwych operacji, ale dla własnoręcznie napisanych operatorów sama kompilacja conceptu nie zastąpi dowodu ich praw matematycznych.

## Porównanie i decyzje

Wprowadzaj concepts na granicy generycznego interfejsu, gdy poprawiają diagnostykę i opisują rzeczywiste wymagania. Ranges wybieraj dla operacji, których sekwencja jest dzięki temu czytelna. Moduły oceniaj razem z systemem budowania i dystrybucją biblioteki. Korutyny przydają się do opisu operacji zawieszanych, ale wymagają biblioteki zarządzającej ich wykonaniem i czasem życia.

Migracja może być stopniowa: pojedynczy komponent używa `span` lub `jthread`, podczas gdy reszta aplikacji zachowuje dotychczasową strukturę. Ustal tylko, czy nowy typ trafia do publicznego nagłówka; wtedy wymaganie standardu przenosi się również na klientów. Funkcja użyta wyłącznie wewnątrz pliku implementacji ma mniejszy zasięg zależności.

## Ćwiczenie z odpowiedzią

Czy przejście z `constinit int counter` na `constexpr int counter` zachowuje możliwość inkrementacji? Nie: `constexpr` czyni taki obiekt `const`. Czy `integral<T>` zapewnia brak signed overflow w sumowaniu? Nie: ograniczenie typu nie dowodzi niczego o rozmiarze konkretnych danych ani ich sumie.
